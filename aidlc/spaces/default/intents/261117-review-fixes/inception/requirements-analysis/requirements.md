# 要件（Requirements）— コードレビューの指摘 1〜6 を直す

## 1. 何をしたいか（Intent Analysis）

依頼（`project-description.json`）:

> コードレビューの指摘 1〜6 を直し、それぞれに再発を見つける確認を足す

- **目的**: 種類ページの型と確認プログラムにある 6 つの不具合を直します。これらは、いまのページにはまだ出ていません。しかし、原稿の書き方しだいで、ページが壊れたり、確認をすり抜けたりします。
- **種類**: 不具合の修正（bugfix）。対象はテンプレート（`site/layouts/`）、確認プログラム（`tools/check/`）、比較ページの原稿です。
- **前の段階で分かったこと**（`codekb/aqua-species-note/`）:
  - 6 つともコード上で確かめられた。
  - 1〜5 は、いまの原稿では表に出ていない。そのため、再発を見つける確認には、わざと壊した入力が要る。
  - 1・2・5 はテンプレートの不具合なので、`hugo` で書き出した結果を調べる確認も必要。

## 2. 機能の要件（Functional Requirements）

| ID | 要件 | 合格の基準 | 出どころ |
|---|---|---|---|
| FR1 | **出典リンクが HTML の属性を壊さない**。`site/layouts/partials/cite.html` は、属性の値（`aria-label`、`alt`、`title` など）の中にある［n］をリンクに変えない。本文の文字の部分にある［n］だけをリンクにする | 表の名前を `{caption="相場［28］"}` にして書き出す。すると、表の名前（caption）の中の［28］はリンクになる。一方、`aria-label="相場［28］"` は書き換えられずに残る。HTML が壊れない | 指摘 1 |

| FR2 | **複数の番号をまとめた出典を扱う**。本文の ［5、6］［5, 6］［5,6］ のような書き方を、リンクにも確認にも入れる。番号ごとに参考文献へのリンクにし、確認プログラム（`citations.py`）も、それぞれの番号が参考文献にあるかを調べる | ［5、6］がリンク 2 つになる。［5、99］（99 番は参考文献にない）は確認で失敗する | 指摘 2 |

| FR3 | **フォルダ形式の原稿も確かめる**。`frontmatter.py` は、`site/content/species/` の下の `*.md` と `*/index.md` の両方を調べる（`_index.md` は除く） | `species/test-sp/index.md` に、壊したフロントマターの原稿を置くと失敗する（テストの中の一時フォルダで確かめる） | 指摘 3 |

## 4. 制約（Constraints）

- `docs/` は手で直さない。`site/` を直したら `hugo` で書き出し、`site/` と `docs/` を同じコミットに入れる。
- コミットと push は本人がする。AI は push しない。
- Hugo 0.158.0 の機能だけを使う（新しい道具は入れない）。

## 5. 前提（Assumptions）

- **A1（FR1 の直し方）**: テンプレートの中で、HTML の「タグの外の文字」だけを置き換える方法をとる。または、［n］をリンクに変える処理を、属性を作る前（Markdown の段階）に移す。どちらにするかは、Code Generation の計画で決める。
- **A2（FR2 の区切り）**: 区切りとして認めるのは「、」「,」「，」の 3 つと、その前後の空白。範囲（〜）との組み合わせ（［4〜6、9］など）も認める。
- **A3（FR4 の決まり）**: refs の区切りは「, 」（いまの決まり）のままとする。ただし、テンプレートは「、」や全角の空白でも止まらないようにする。確認プログラムは、決まりに合わない書き方を分かりやすく失敗にする。
- **A4（FR6 の直し方）**: Hugo では、ほかのページの更新日から比較ページの更新日を自動で決めにくい。そのため、手で直す方法と、忘れたら確認が知らせる方法を組み合わせる。
- **A5**: 指摘 7〜10（作りの改善）は、今回の範囲の外とする。

## 6. 範囲の外（Out of Scope）

- 指摘 7〜10（表の差し込み方、出典リンクの処理が 2 か所あること、メニューと日付の重なり、サイト内リンクの確認の書き方）。
- GitHub Pages が CI の結果に関係なく公開すること（前の段階で見つかった点）。
- 原稿の中身の変更（比較ページの更新日を除く）。
