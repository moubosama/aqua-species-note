# 自分で作るか、既存の場を使うか（Build vs Buy）

意図の整理（`ideation/intent-capture/intent-statement.md`）では、中身はほぼ全部無料で公開し、有料販売と広告は最初の版に入れないことにしました。その前提で、記事を置く場所を比べます。回答は market-research-questions.md の Q 番号で示します。

## 1. 比べた案

| 観点 | A. 今の Hugo サイト（GitHub Pages） | B. note など既存のブログサービス | C. 両方（本体はサイト、要約と告知は note） |
|---|---|---|---|
| 費用 | 0円（今の公開方法のまま） | 0円（無料の範囲） | 0円 |
| 比較表・要点の表の自由度 | 高い。テンプレートで全種そろえられる | 低い（仮説。表の機能は限られる） | 本体は高い |
| 出典番号や章立てをそろえる | テンプレートで決められる | 記事ごとに手作業（仮説） | 本体はテンプレート |
| 検索で見つかる | 自分で対策する（構造化データ・サイトマップ） | サービス側の集客がある（仮説） | 両方の入口がある |
| 読者が集まる場 | ない（検索だけ） | note の中で見つけてもらえる（仮説） | note から本体へ誘導できる |
| データを自分で持てる | 持てる（Markdown のまま） | サービスに依存する | 本体は持てる |
| 手間 | テンプレートを作る手間がかかる | 少ない | 要約を書く手間が増える |
| 将来の有料化（PDF・Kindle） | 同じ原稿から作りやすい（仮説） | note の有料記事は使える | どちらも選べる |

## 2. 決定（Q6: C）

**本体は今の Hugo サイトに置き、要約や告知を note に書きます。**

- 差別化の柱（繁殖記録の比較表、出典と信頼度の表示）は、テンプレートで全種そろえる必要があり、本体は自分のサイトが向いている。
- 意図の整理で決めた告知（更新履歴、note・Instagram、月1回のまとめ）と合う。
- 中身を自分の手元に Markdown で持てるので、将来の PDF・Kindle 化にも使える（仮説）。

## 3. 協力（Partner）

自分で作らず借りるものは、記録と写真です。情報提供者（繁殖者・ブロガー）と海外の研究プロジェクトやデータベースに連絡し、使用許可をもらいます（Q8: B）。手順は要件の段階で決めます。

## Assumptions & Open Questions

- note の表機能、集客、有料記事についての見立ては仮説で、今回は確かめていない。
- note に書く要約の量と頻度（月1回のまとめとの関係）は、範囲の段階で決める。
