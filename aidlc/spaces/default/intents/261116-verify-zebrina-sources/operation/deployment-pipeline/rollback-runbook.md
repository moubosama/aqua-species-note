# 戻し方の手順（Rollback Runbook）

チームの決まり（team.md「戻し方」）のとおり、問題のコミットを打ち消すコミットを作り、本人が push して元に戻します。履歴を書き換える操作（強制 push など）はしません。

## 戻すきっかけ

- push のあと、GitHub Actions の `check` が失敗した。
- 公開先でページが表示されない、リンクが切れている、表が崩れている。
- 公開した数字や引用に誤りが見つかり、すぐには直せない。

## 手順

1. 問題のコミットを探します。

   ```
   git log --oneline -5
   ```

2. そのコミットを打ち消すコミットを作ります。

   ```
   git revert <コミットの番号>
   ```

   - `site/` と `docs/` は同じコミットに入っているので、両方が一緒に元に戻ります。

3. 戻したあとの手元の状態で、確認 3 つが失敗 0 件で通ることを確かめます。

   ```
   hugo --source site --cleanDestinationDir
   python tools/check/run_checks.py docs
   py -3.12 -m unittest discover -s tools/check/tests
   ```

   - `hugo` で書き出し直して `docs/` に差が出たときは、その差もコミットします。

4. 本人が `main` に push します。

5. 公開先で、元の表示に戻ったことを確かめます（`deployment-strategy.md` の「公開のあとの確かめ」と同じ手順です）。

## 今回の変更に特有のこと

- 今回の変更を戻すと、確認プログラムの `status` の決まりも一緒に元に戻ります。
- 原稿だけを戻して、確認プログラムを残すと、原稿に `status` がないため frontmatter の確認が失敗します。
- そのため、戻すときはコミットを丸ごと戻してください。

## 連絡先

本人 1 人で運用しているので、連絡や引き継ぎの先はありません。
